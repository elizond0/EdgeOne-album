发布确认

编辑不需要口令。真正写回仓库时才验一次身份——口令发给家里 NAS 的写入口核对，本机不存哈希。

有未发布的改动

「保存并发布」把 content.json 交给家里 NAS 上的写入口（album-push.py）， 由它替你先验一遍再提交：照片文件名是否真在 NAS 上、照片数有没有骤降、旧版留档。 校验过了才推送仓库，GitHub Pages 约 20~60 秒重建，Ctrl/Cmd+Shift+R 强刷可见。
口令在点「保存并发布」时输入，只用于让 NAS 写入口核对身份（NAS 侧只存加盐哈希，token 不进浏览器）。 NAS 不在线时，可以在下面填一个 GitHub Token 走直连；两条都不通还有「仅下载」。 照片文件本身不需要在这里传——放进 NAS 的照片目录即可。

GitHub Token（备用 · NAS 不在线时直连） 未设置

平时不用填。只有 NAS 断电/断网、写入口连不上时才需要它兜底。 建一个 Fine-grained token：Repository access 只选 elizond0/album， Permissions 只勾 Contents → Read and write，有效期建议 90 天。 token 只存在当前标签页的 sessionStorage，关掉标签页即失效，不会写进 localStorage。
