## 2. 归类是怎么做的（实测口径）

### 2.1 地点 → 标题

照片的 `title` 不是文案，是**地名归类**。562 张里只有 11 个唯一值：

| title | 张数 |
|---|---|
| 上海·崇明 | 173 |
| 杭州 | 118 |
| 上海 | 80 |
| 苏州 | 62 |
| 杭州·灵隐寺 | 33 |
| 无锡 | 32 |
| 无锡·太湖 | 26 |
| 湖州·南浔 | 15 |

城市维度（`place.city`）覆盖 554/562：上海 268、杭州 151、苏州 62、无锡 58、湖州 15。

**判据**：`place` 五个字段（country / province / city / district / spot）都留空是合法的，
前端只按非空字段拼接显示；不要为凑满而填省级重复值。

### 2.2 GPS

556/562 有 `lat`/`lon`（来自 EXIF）。缺失的 6 张是没有 GPS 的截图或转发图，**不要**用城市中心坐标补——
那会让地图上出现 6 个一模一样的点。

### 2.3 行程事件

4 个事件，通过 `eventId` 关联 107 张照片：

| 事件 | 日期 | 照片数 |
|---|---|---|
| 端午崇明行 | 2026-06-19 | 54 |
| 翘班去苏州 | 2026-05-15 | 38 |
| 无锡两日 | 2026-05-02 | 14 |
| 杭州·灵隐寺之行 | 2026-08-21 | 1 |

**判据**：一天里跨两个城市时，按「当天主要停留地」归，不按第一张照片的 GPS。
其余 455 张 `eventId` 为 `null` 是正常的——日常照没有行程可归。

### 2.4 `tags` 是空的（0/562）

标签体系建了但从来没录过。**别再宣称「照片有标签」**：所有归类都靠
`title`（地名）+ `place` + `eventId` + `date`。要启用标签得先定一套受控词表，
否则会退化成各写各的自由文本。

## 3. 备忘录 → 站点的三块内容

`备忘录.docx` 是按日期的日记（`notes_full.txt` 是它的纯文本抽取）。人工读完之后拆成三块：

| 产物 | 条数 | 来自备忘录的哪里 | 加工规则 |
|---|---|---|---|
| `timeline` | 13 | 正文里明确的「第一次 / 开始 / 那天」 | 只保留**有确切日期**的节点；`date` 统一 `YYYY.MM.DD` 显示、`YYYY-MM-DD` 存储 |
| `quotes` | 6 | 原句摘录 | 一字不改，只去掉前后空白；不合并多条 |
| `wishes` | 12 | 「置顶🔝：计划！」那份编号清单 | 逐条搬，原文保留（「坐很久很久的火车去西藏」这种啰嗦的也要原样），每条配一个 emoji |

**判据**：
- 备忘录里的日期是相对表述（「上周三」）→ **不猜**，除非同段里另有绝对日期可锚定
- 同一天有多条记录 → `timeline` 只取一条最有代表性的，其余不进（避免同一天堆五条）
- 语录不做「润色」，改了就不是原话

## 4. 照片日期与备忘录的对齐

照片的 `date` 来自 EXIF 拍摄时间（562/562 全有），**不来自文件名**。
文件名里的 `(20260613-162348)` 是微信/转发留下的，与拍摄时间无关。

对齐时只做一件事：按 `date` 把照片排进时间轴，**不做「这条日记配哪张图」的人工绑定**——
那需要逐张看，562 张的成本远大于收益。

## 5. 要重做一遍的最短路径

```text
① 从网盘/ NAS 拉回 562 张原片 + 备忘录.docx
② 抽 EXIF → 得到每张的拍摄时间 / GPS / 尺寸
③ 按 GPS 聚簇 + 人工确认 → 填 place 五字段 + title（地名）
④ 按日期段落切分 → 填 eventId（只在有行程时）
⑤ 读备忘录 → 抽 timeline / quotes / wishes（口径见 §3）
⑥ 写进 data/seed.json（结构照现有文件抄，字段名别改）
⑦ python3 scripts/build_content.py → 生成 data/content.json
```

**第 ⑥ 步是唯一必须人工的**：地名归类和「哪张照片属于哪次出行」没有可靠算法，
靠看图和回忆。当年 562 张大约分了 11 个地点簇，是逐个确认过的。

## 6. 为什么这些中间产物没进仓库

仓库 `elizond0/album` 是**公开**的。`notes_full.txt` 是从私人日记抽出来的全文，
一旦提交就是永久公开（git 历史删不干净）。所以它只留在临时工作区，**这是故意的，不是遗漏**。

同样，`exif.json` 含 556 个精确 GPS 坐标——家庭住址级别的定位精度，不适合公开。
`content.json` 里的 GPS 是同样的数据，这点**已经是既成事实**（站点靠它做地图），
但不要再往仓库里多加一份明文原始 EXIF。
