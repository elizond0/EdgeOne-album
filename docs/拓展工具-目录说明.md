# 拓展工具（NAS 自研工具统一存放区）

> **位置**：共享文件夹根目录下的 `拓展工具/`（原「照片视频」文件夹，2026-11-16 改名）。
> **作用**：所有跑在 NAS 上的自研工具，资源与代码统一放这里。一个工具一个子目录，互不干扰。
> **容器**：`共享文件夹/docker/` 是 Docker 套件的数据目录（绿联 Docker 应用自带），**不是本目录的一部分**，
> 本目录下不新建 docker 项目。

## 一、现行工具

| 子目录 | 作用 | 运行载体 | 文档 |
|---|---|---|---|
| `照片展示/` | 恋爱纪念册相册的公网发布链路（压缩图、缩略图、转码视频、隧道地址自愈、后台写入口） | 容器 `album-node`，容器内 `/srv/pub` | `相册展示/部署必读.md` |

## 二、`照片展示/` 的内部结构

```
拓展工具/照片展示/
├── csy/          → 容器 /srv/csy      【只读】压缩图与视频的源（原图原片）
├── album-pub/    → 容器 /srv/pub      【可写】唯一对外发布目录
└── ts-state/     → 容器 /var/lib/tailscale 【可写】脚本、隧道凭据、原片备份 orig_video
```

三条硬约定：

1. **`csy/` 是只读挂载**。任何脚本都不许写它 —— 一旦挂成可写，误删/误改名就没有第二份了。
2. **只有 `album-pub/` 对外**。公网能访问到的目录就这一个，`index.json` 与 `img/`、`video/` 都在里面。
3. **`ts-state/orig_video/` 是视频原片的唯一备份**（手机原码 16 个、286 MB）。迁移目录时不要动它，
   换成别的机器/重建容器之前先单独拷出来。

## 三、新增工具时的约定

1. **有 Docker 的一律用 Docker**：先看 `共享文件夹/docker/` 下有没有现成容器可用；
   自带镜像的工具，子目录里放 `docker-compose.yml` + 一个数据目录，不往宿主机塞进程。
2. **没有 Docker 的**：在该工具子目录下新建文件夹，程序、配置、日志都放里面，
   不要散落到共享文件夹根目录。
3. **每个工具目录里写自己的 `部署必读.md`**，登记四件事：端口、挂载、依赖、口令指针
   （明文只写「见云盘根目录 `凭据.md` §N」，不写明文、不写 file_id）。
4. **不要复用别的工具的目录**。共用目录会导致「删一个工具带崩另一个」，
   也会让「这个文件到底谁在用」永远说不清。

## 四、为什么要有这份文件

2026-11-16 之前，原图放在 `共享文件夹/Photos/`，压缩产物放在 `共享文件夹/照片视频/`，
两份文档里各写一套「哪个是原片、哪个是副本」，实际却是 `csy` 已在 `Photos` 里面、
两者同一份数据。排查时先要花时间分辨「文档说的源头」和「容器里真正挂的源头」是不是一回事。

所以这里立一条：**目录结构只在本文件登记一次**，其他文档只写指针。
容器里真实挂载以 `mount | grep srv` 为准，文档与实测不一致时，改文档。
