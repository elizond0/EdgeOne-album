# 拓展工具 —— 目录说明

> **位置**：`共享文件夹/拓展工具/`
> **作用**：NAS 上所有自研工具的资源与代码统一放这里，一个工具一个子目录，互不干扰。
> **Docker 数据目录**：`共享文件夹/docker/` 是绿联 Docker 应用自带的存储目录（现有 qinglong 等），与本文目录**平级**，本目录下不新建 docker 项目。
> **最后核对**：2026-11-17 15:40（容器重建后实测，`mount` 与实测一致）

## 一、现行结构

```text
共享文件夹/
├── Photos/
│   └── csy/                     → 容器 /srv/csy（只读）
│                                  原图原片唯一入口：562 图 + 16 视频，共 578 项
└── 拓展工具/                     ← 本目录，自研工具区
    ├── docker-compose.yaml       album-node 项目的 compose（项目「存放路径」= 本目录）
    ├── 目录说明.md                本文件
    ├── ts-state/                 → 容器 /var/lib/tailscale（读写）
    │                              cloudflared 凭据、boot.sh / Caddyfile / base-sync.sh、orig_video 原片备份
    └── 照片展示/                  → 容器 /srv/pub（读写）· 唯一对外发布目录
        ├── img/                  压缩图 562 张（长边 2048 / q85 / 去 EXIF）
        │   └── t/                网格缩略图（长边 720，体积约 12%）
        ├── video/                转码视频 16 个（HLG→H.264 SDR）
        │   └── poster/           每个视频的首帧封面
        ├── index.json            清单（图 + 视频 + 缩略图/封面路径），站点读它
        ├── index.html
        └── base.json             当前隧道地址，由 base-sync.sh 每 5 分钟自愈同步
```

## 二、四条硬约定

1. **`Photos/csy/` 只读挂载**（compose 里 `:ro`，容器内 `mount | grep srv/csy` 显示 `ro`）。
   任何脚本都不许写它——UGOS 相册靠 EXIF 建索引，动了元信息索引就散；只读挂载让误写直接报 EROFS，而不是悄悄改坏。
2. **只有 `照片展示/` 对外**。Caddy 在 `:8443` 上把 `/srv/pub` 静态发出去，cloudflared 再接公网。能通过公网访问到的目录就这一个。
3. **`ts-state/` 必须留在 `照片展示/` 之外**。它存的是 cloudflared 隧道凭据和启动脚本，
   一旦放进 `照片展示/`，等于把隧道私钥挂到公网静态目录上。位置换不得。
4. **compose 用相对路径**：`../Photos/csy`、`./照片展示`、`./ts-state`。
   所以 UGOS 建项目时「存放路径」**必须手选 `共享文件夹/拓展工具`**；
   系统默认给的是 `共享文件夹/docker/album-node`，选错就是三个挂载全指向空目录——**站点能打开、但一张图都没有**。
   实测：「重新部署」按钮**不会**重建容器，挂载沿用创建时那张表；改挂载只能删项目后重新导入。

## 三、新增工具怎么放

1. **有 Docker 的**：先看 `共享文件夹/docker/` 有没有现成容器可用；
   自建镜像的，在 `拓展工具/<工具名>/` 下放 `docker-compose.yml` + 一个数据目录，不往宿主机塞常驻进程。
2. **没有 Docker 的**：在 `拓展工具/<工具名>/` 下放程序、配置、日志，不要散落到共享文件夹根目录。
3. **每个工具目录里写自己的《部署必读》**：登记端口、挂载、依赖、口令指针
   （明文只写「见云盘根目录《凭据.md》§N」，不写明文、不写 file_id）。
4. **不要复用别的工具的目录**。共用目录会导致「删一个工具带崩另一个」，也会让「这个文件到底谁在用」永远说不清。

## 四、为什么要有这份文件

2026-11-16 之前，原图在 `共享文件夹/Photos/`，压缩产物在 `共享文件夹/照片视频/`，
两份文档里各写一套「哪个是原片、哪个是副本」，实际却是同一份数据；排查时先要花时间分辨
「文档说的源头」和「容器里真正挂的源头」是不是一回事。

立一条规矩：**目录结构只在本文件登记一次**，其他文档只写指针。
容器里真实挂载以 `mount | grep srv` 为准，文档与实测不一致时改文档。
