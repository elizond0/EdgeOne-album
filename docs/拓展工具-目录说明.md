# 照片视频（= 拓展工具区）目录说明

> **位置**：`共享文件夹/照片视频/`
> **为什么还叫「照片视频」**：原计划把共享文件夹改名为「拓展工具」，但 UGOS 的**共享文件夹根目录不支持重命名**
> （系统托管，右键菜单里没有重命名项；只有它下面的子文件夹才能改名）。要么保留原名，要么新建一个共享文件夹再把数据搬过去。
> 现在选的是**保留原名**——名字叫「照片视频」，**职责就是拓展工具区**。本文与其他文档一律按这个口径写，
> 别再去 NAS 上找「拓展工具」这个文件夹，它不存在。
>
> **作用**：所有跑在 NAS 上的自研工具，资源与代码统一放这里。一个工具一个子目录，互不干扰。
> **Docker 数据目录**：`共享文件夹/docker/` 是绿联 Docker 应用自带的存储目录（现有 qinglong 等），
> **不是本目录的子目录**，本目录下也不新建 docker 项目。

## 一、现行工具

| 子目录 | 作用 | 运行载体 | 文档 |
|---|---|---|---|
| `照片展示/` | 恋爱纪念册相册的公网发布链路（压缩图、缩略图、转码视频、隧道地址自愈、后台写入口） | 容器 `album-node` | 云盘 `相册展示/部署必读.md` |

## 二、实测结构（2026-11-17 核对）

```
共享文件夹/照片视频/                      ← 即「拓展工具」区
├── docker-compose.yaml                  ← album-node 项目的 compose（项目「存放路径」= 本目录）
├── csy/            → 容器 /srv/csy       【只读】原图原片（562 图 + 16 视频源）
├── ts-state/       → 容器 /var/lib/tailscale 【可写】boot.sh、Caddyfile、cloudflared 凭据、base-sync.sh
└── 照片展示/
    └── album-pub/  → 容器 /srv/pub       【可写】唯一对外发布目录（44 项：img/ video/ index.json index.html base.json …）
```

> 2026-11-17 清理完成，`照片视频/` 根下只剩 `docker-compose.yaml` + `csy/` + `ts-state/` + `照片展示/`（4 项工具本体）+ 本文：
> ①迁移时 Docker 自动建的旧路径空壳 `album-pub/`（只有空 `video/poster/`）已删进回收站；
> ②来源不明的 `album/`（`sub/`、`boot.log`、`daemon.log`、`index.html` 9 B、`t.bin` 8 MB）已按使用者要求删进回收站，与发布链路无关。

四条硬约定：

1. **`csy/` 是只读挂载**（compose 里 `:ro`，容器内 `mount | grep srv/csy` 显示 ro）。
   任何脚本都不许写它——一旦挂成可写，误删/误改名就没有第二份了。
2. **只有 `照片展示/album-pub/` 对外**。公网（Caddy `:8443` + cloudflared）能访问到的目录就这一个。
3. **`ts-state/` 是容器的「记忆」**：里面是启动脚本、隧道凭据和 `base-sync.sh`。
   重建容器时它必须原样挂回去，否则隧道域名会变、`base.json` 要重新同步。
4. **compose 用相对路径**（`./csy`、`./照片展示/album-pub`、`./ts-state`），
   所以 UGOS 里创建/重建项目时「存放路径」**必须选 `共享文件夹/照片视频`**，不能让它默认落到 `共享文件夹/docker/album-node`——
   选错路径，三个挂载全部指向空目录，站点会看起来「没有数据」。

## 三、新增工具时的约定

1. **有 Docker 的一律用 Docker**：先看 `共享文件夹/docker/` 下有没有现成容器可用；
   自带镜像的工具，在本目录下建子目录，放 `docker-compose.yml` + 一个数据目录，不往宿主机塞进程。
2. **没有 Docker 的**：在本目录下新建工具子目录，程序、配置、日志都放里面，
   不要散落到共享文件夹根目录。
3. **每个工具目录里写自己的 `部署必读.md`**，登记四件事：端口、挂载、依赖、口令指针
   （明文只写「见云盘根目录 `凭据.md` §N」，不写明文、不写 file_id）。
4. **不要复用别的工具的目录**。共用目录会导致「删一个工具带崩另一个」，
   也会让「这个文件到底谁在用」永远说不清。

## 四、为什么要有这份文件

2026-11-16 之前，原图放在 `共享文件夹/Photos/`，压缩产物放在 `共享文件夹/照片视频/`，
两份文档里各写一套「哪个是原片、哪个是副本」，实际却是同一份数据。
排查时先要花时间分辨「文档说的源头」和「容器里真正挂的源头」是不是一回事。

所以这里立一条：**目录结构只在本文件登记一次**，其他文档只写指针。
容器里真实挂载以 `mount | grep srv` 为准，文档与实测不一致时，改文档。
